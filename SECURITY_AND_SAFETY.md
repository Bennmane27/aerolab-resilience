# Security and safety

## What this project is

A simulation. Every "attack" in it is arithmetic applied to an array of doubles
that a simulated sensor produced a few microseconds earlier, inside a single
process, on one machine.

## What this project contains

Fourteen scenarios that degrade synthetic navigation measurements, and five
navigation architectures that try to cope. The degradations are named after real
failure modes — loss, freeze, bias, drift, latency, spoof — because those are the
names of the phenomena being modelled.

## What this project does not contain

There is no radio. There is no signal generator, no modulation, no carrier, no
code, no software-defined radio interface and no driver for one. There is no
receiver model beyond a position-velocity output with a noise model. There are no
transmission parameters, no power levels, no frequency plans, and no operational
procedure for interfering with any real system. Nothing here can be pointed at
anything.

The word **spoofing** in this repository means exactly one thing: adding a number
to a synthetic position that never left this program. `FaultInjectionEngine::apply`
takes a vector of measurements and returns nothing else; it is not given a handle
to the ground truth, let alone to hardware.

Grep the source. The words `frequency`, `transmit`, `antenna`, `SDR` and `RF`
appear in this file and nowhere in `core/`.

## Why the boundary is drawn in the type system

`AT-002` and `VNV-002` exist because the separation between the truth and the
measurements is the property that makes every number in this project meaningful.
It is enforced by the signature of the fault engine rather than by convention, so
that no future change can quietly make the truth — or anything else — reachable
from the fault path.

The same reasoning applies to the safety boundary. There is no module that could
be given a radio because there is no abstraction in the codebase that a radio
could be plugged into.

## Not for flight

This software is a research and engineering demonstrator. It is not airworthy, not
certified, not certifiable in its present form, and must not be installed in,
connected to, or used to make decisions about any aircraft, vehicle or vessel.

No claim of conformance to DO-178C, DO-254, ARP4754A, RAIM, ARAIM, or any other
standard is made anywhere in this repository. Where the code implements something
that resembles a standardised technique — the residual test in
`core/src/integrity/raim.cpp`, the solution separation in
`core/src/navigation/solution_separation.cpp` — the file says in its own header
that it is educational and that no conformance is claimed.

## Data

No personal data, no confidential data and no proprietary data is used, embedded
or produced. Every input is generated by the code in this repository from a seed.

## Reporting a problem

If you believe something here crosses the boundary described above, open an issue
citing the file and the line. That is a defect, and it will be treated as one.
